知识库项目 — 架构与功能设计

文档版本 1.0 · 2026-09-21 · FastAPI + Vue 3 · MySQL + Elasticsearch

1. 项目概述

📝

个人笔记知识库

类似 Obsidian 的 Markdown 笔记系统，支持双向链接、标签分类、版本历史

🤖

AI 智能问答

基于 RAG 架构，结合知识库内容进行 AI 对话，支持流式回答与引用溯源

📄

文档上传与解析

支持 PDF/Word/Markdown/网页等格式的文档上传、内容提取与向量化

🔗

知识图谱

自动从笔记双向链接中构建知识图谱，可视化展示笔记间的关联关系

🔍

全文搜索

Elasticsearch 驱动的高性能搜索，支持多字段检索、分面过滤、高亮与联想

👥

权限与协作

用户认证、角色权限、知识空间共享，支持个人空间与团队协作

设计目标：构建一个集笔记编辑、知识管理、AI 问答、文档解析于一体的高性能个人知识库平台。支持 Markdown 双向链接构建知识网络，Elasticsearch 提供秒级全文检索，RAG 架构实现智能问答，并通过知识图谱可视化知识关联。

3. 系统架构

3.1 整体架构图

3.2 架构说明

  • 客户端层：Vue 3 SPA，通过 Nginx 反向代理访问后端 API。笔记编辑器使用 Milkdown 提供所见即所得编辑体验，知识图谱使用 vis-network 力导向布局渲染。
  • 应用层：FastAPI 提供 RESTful API 和 WebSocket（AI 流式对话）。API 路由层只做参数校验和响应封装，业务逻辑下沉到 Service 层。
  • 异步任务层：Celery Workers 处理耗时任务——文档解析（PDF/Word 文本提取）、文本分块、Embedding 向量化、ES 索引同步。通过 Redis 作为消息代理实现任务分发。
  • 数据层：MySQL 存储结构化业务数据，Elasticsearch 同时承担全文搜索和向量检索（dense_vector 字段），Redis 负责缓存和 Celery broker，MinIO 存储上传的原始文件。
  • AI 层：LangChain 编排 RAG 流程——检索（ES 向量 + 全文混合检索）→ 重排序 → LLM 生成。支持 OpenAI/Anthropic/本地模型，通过统一接口切换。

5. API 接口设计

所有 API 以 /api/v1 为前缀，使用 JWT Bearer Token 认证（除 auth 端点外），响应统一包装为 {"code": 0, "data": ..., "message": "ok"} 格式。

5.1 认证接口 (Auth)

POST/api/v1/auth/register用户注册
POST/api/v1/auth/login用户登录，返回 access + refresh token
POST/api/v1/auth/refresh刷新 access token
GET/api/v1/auth/me获取当前用户信息
PUT/api/v1/auth/me更新个人资料

5.2 笔记接口 (Notes)

GET/api/v1/notes?page=1&size=20&space_id=&tag=笔记列表（支持过滤分页）
POST/api/v1/notes创建笔记
GET/api/v1/notes/{id}获取笔记详情
PUT/api/v1/notes/{id}更新笔记（自动保存版本）
DEL/api/v1/notes/{id}删除笔记
GET/api/v1/notes/{id}/backlinks获取反向链接笔记列表
GET/api/v1/notes/{id}/versions获取笔记版本历史
GET/api/v1/notes/{id}/graph获取笔记局部图谱

5.3 文档接口 (Documents)

POST/api/v1/documents/upload上传文档（multipart，触发异步解析）
GET/api/v1/documents?page=1&size=20文档列表
GET/api/v1/documents/{id}文档详情（含解析状态）
GET/api/v1/documents/{id}/content获取文档提取的文本内容
DEL/api/v1/documents/{id}删除文档

5.4 搜索接口 (Search)

GET/api/v1/search?q=keyword&type=all&tag=&space_id=全文搜索（笔记 + 文档）
GET/api/v1/search/suggest?q=key搜索联想/自动补全
GET/api/v1/search/semantic?q=语义查询向量语义搜索

5.5 AI 对话接口 (AI / RAG)

POST/api/v1/ai/sessions创建对话会话
WS/api/v1/ai/ws/{session_id}流式对话（WebSocket 推送）
GET/api/v1/ai/sessions会话列表
GET/api/v1/ai/sessions/{id}/messages会话消息历史
DEL/api/v1/ai/sessions/{id}删除会话

5.6 知识图谱接口 (Graph)

GET/api/v1/graph?space_id=&depth=2全局知识图谱（nodes + edges）
GET/api/v1/graph/note/{id}?depth=2笔记局部图谱

5.7 标签接口 (Tags)

GET/api/v1/tags标签列表
POST/api/v1/tags创建标签
PUT/api/v1/tags/{id}更新标签
DEL/api/v1/tags/{id}删除标签

5.8 知识空间接口 (Spaces)

GET/api/v1/spaces空间列表
POST/api/v1/spaces创建空间
PUT/api/v1/spaces/{id}更新空间
POST/api/v1/spaces/{id}/members添加空间成员
PUT/api/v1/spaces/{id}/members/{user_id}更新成员角色
DEL/api/v1/spaces/{id}/members/{user_id}移除成员

7. Elasticsearch 索引设计

设计策略：Elasticsearch 同时承担全文搜索和向量语义检索双重职责。使用 dense_vector 字段存储 Embedding，配合 kNN 查询实现语义检索。搜索时采用混合策略：BM25 全文检索分数 + kNN 向量相似度分数加权融合。

10. 笔记管理与双向链接

10.1 双向链接机制

用户在 Markdown 中使用 [[笔记标题]] 语法引用其他笔记。保存时系统自动解析所有链接，更新 note_links 表。

链接解析规则

  • [[笔记标题]] — 按标题精确匹配，匹配不到则显示为红色（悬空链接）
  • [[笔记标题|显示文本]] — 自定义显示文本
  • [[笔记标题#章节]] — 链接到笔记的特定章节
  • 保存笔记时，diff 新旧链接集合：新增的插入 note_links，删除的移除
  • 目标笔记被删除时，级联清理所有相关 note_links 记录

10.2 版本管理

  • 每次保存（非自动保存）时创建一个版本快照，存入 note_versions
  • 自动保存（每 30 秒）不创建版本，仅更新 content
  • 版本对比：前端使用 diff 算法高亮差异
  • 支持回滚到任意历史版本
  • 默认保留最近 50 个版本，超出自动清理最旧版本

11. 文档上传与解析

11.1 解析流水线

支持的文档格式与解析库

格式扩展名解析库说明
PDF.pdfPyMuPDF (fitz)提取文本 + 页码元数据
Word.docxpython-docx提取段落 + 标题层级
Markdown.md / .markdownmarkdown-it直接使用原文
纯文本.txt内置直接读取
HTML.html / .htmBeautifulSoup4提取正文，去除导航等噪声
EPUB.epubEbookLib提取章节文本

分块策略

  • 使用 LangChain 的 RecursiveCharacterTextSplitter，优先按段落 → 句子 → 字符递归分割
  • 每块目标 512 tokens，重叠 64 tokens（保证上下文连续性）
  • 保留元数据：页码、章节标题、文档 ID
  • 分块结果存入 document_chunks 表和 documents_index

12. AI 对话与问答 (RAG)

12.1 RAG 流程图

12.2 关键设计

  • 检索范围：默认检索当前用户的所有笔记 + 已完成解析的文档。可通过 space_id 限定搜索范围。
  • Top-K 检索：BM25 和 kNN 各取 Top-10，RRF 融合后取 Top-5 作为 LLM 上下文。
  • Prompt 模板：包含系统提示（角色 + 规则）、检索到的上下文片段（带来源标注）、对话历史（最近 6 轮）、用户当前问题。
  • 引用溯源：LLM 回答中标记引用编号 [1] [2]，sources 字段存储对应的笔记/文档片段元信息，前端渲染为可点击的引用链接。
  • 流式响应：通过 WebSocket 将 LLM 的流式输出实时推送到前端，避免长时间等待。
  • 模型切换：支持配置不同的 LLM 提供商（OpenAI GPT-4 / Anthropic Claude / 本地 Ollama），通过环境变量切换。

13. 全文搜索与标签

13.1 搜索能力

功能实现方式说明
关键词搜索ES BM25 + IK 中文分词支持中英文混合搜索，IK 插件提供智能分词
多字段检索multi_match (title^3, content^1, excerpt^2)标题权重最高，摘要次之，正文最低
分面过滤aggregation按标签、空间、时间范围、文档类型聚合过滤
搜索高亮highlight匹配关键词高亮显示
搜索联想completion_suggester输入时实时推荐补全词
语义搜索kNN dense_vector基于向量相似度的语义级检索
排序选项sort相关度 / 创建时间 / 更新时间

13.2 索引同步策略

  • 笔记保存：Celery 异步任务将笔记内容同步到 notes_index
  • 文档解析完成：将所有 chunk 同步到 documents_index
  • 笔记删除：从 ES 索引中删除对应文档
  • 重建索引：提供管理接口，从 MySQL 全量重建 ES 索引（用于初始化或修复）

14. 权限与协作

14.1 认证机制

  • JWT 双令牌：Access Token（30 分钟有效期）+ Refresh Token（7 天有效期，存 Redis）
  • 密码安全：bcrypt 哈希 + 密码强度校验（最少 8 位，含字母数字）
  • 令牌刷新：Access Token 过期后用 Refresh Token 换取新令牌，无需重新登录
  • 登出：将 Refresh Token 从 Redis 删除，使其失效

14.2 RBAC 权限模型

角色个人空间共享空间系统管理
admin完全控制完全控制 + 成员管理用户管理、系统配置
editor完全控制读写笔记/文档—
viewer完全控制只读—

14.3 知识空间 (Spaces)

  • 个人空间：每个用户自动创建一个默认个人空间，笔记默认归属此空间
  • 共享空间：用户可创建共享空间，邀请其他用户加入，分配 editor/viewer 角色
  • 空间隔离：笔记、文档、搜索均按空间维度隔离，用户只能访问自己有权限的空间
  • 公开分享：生成带过期时间的分享链接，无需登录即可只读访问指定笔记
